Представь, что тебе нужно выделить подсети под различные сегменты организации
 N — технологический (3 машины), серверный (16 машин) и пользовательский (из 32 машин).

	Подсчет минимального размера каждой подсети:
Технологический (3 устройства):
Требуется: 3 + 2 = 5 IP
Ближайшая степень двойки: 2^3 = 8 → /29 (маска 255.255.255.248)
Серверный (16 устройств):
Требуется: 16 + 2 = 18 IP
Ближайшая степень двойки: 2^5 = 32 → /27 (маска 255.255.255.224)
Пользовательский (32 устройства):
Требуется: 32 + 2 = 34 IP
Ближайшая степень двойки: 2^6 = 64 → /26 (маска 255.255.255.192)
Пример разбиения (с IP-базой, скажем, 192.168.0.0/24)

	Раздаём сначала самые большие подсети, потом меньшие (это важно в VLSM):
    1. Пользовательский сегмент – 64 IP → /26
Подсеть: 192.168.0.0/26
Диапазон хостов: 192.168.0.1 – 192.168.0.62
Широковещательный: 192.168.0.63
    2. Серверный сегмент – 32 IP → /27
Подсеть: 192.168.0.64/27
Диапазон хостов: 192.168.0.65 – 192.168.0.94
Широковещательный: 192.168.0.95
    3. Технологический сегмент – 8 IP → /29
Подсеть: 192.168.0.96/29
Диапазон хостов: 192.168.0.97 – 192.168.0.102
Широковещательный: 192.168.0.103
		3 пункт
	Шаг 1: Учет дополнительных адресов
Каждая IP-сеть (подсеть) всегда теряет 2 адреса:
один – на сетевой адрес
один – на широковещательный (broadcast)
👉 Значит, если нужно подключить N устройств, реально требуется N + 2 IP-адреса в подсети.
